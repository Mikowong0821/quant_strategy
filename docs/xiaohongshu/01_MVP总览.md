# 01｜MVP 总览：一条命令讲完「研究侧」

**发笔记用标题（可改）：**  
量化工程｜为什么我先做「能跑全链路」的 MVP，而不是一口吃实盘？

---

**正文（可复制改写）**

很多人理论都懂，一写代码就断在某一环。这个仓库 **Quant Strategy** 干的事很简单：用 **一条主流程** 把研究侧串死。

跑通一次，你等于在真实目录里走完了：  
**数据 → 因子 → IC → 多因子融合 → 回测 → 绩效和图**。

命令就一句：`python main.py`。  
默认四列单因子各一条净值，再加一条 **融合** 净值，IC 和图都能对齐到同一套日历——后面你改因子、改融合、改配权，才有「对照实验」可做。

MVP 不是偷懒，是先把 **管道噪声** 压下去，再谈 alpha。

**本篇串起来的量化核心点：**  
研究闭环长什么样；为什么「单一入口」比散脚本更值钱。
