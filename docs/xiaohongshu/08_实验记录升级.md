# 08｜这次给 MVP 补了实验运行记录

## 发布标题

量化工程｜回测不是跑完就结束，还要留下实验档案

## 正文

今天给 `Quant Strategy` 这个 MVP 补了一层很实用的能力：**实验运行记录落盘**。

以前跑完 `python main.py`，主要看终端输出和几张图。

但过几天再回头，你可能已经忘了：

- 当时 `top_k` 是多少？
- 用的是等权、最大夏普还是风险平价？
- 手续费率是多少？
- 融合有没有用 IC 滞后滚动列权？
- 每条策略最后的绩效是多少？
- 每期到底买了哪些股票？

所以这次新增三个输出：

```text
output/cache/run_config.json
output/performance_summary.csv
output/rebalance_logs/*.csv
```

分别回答三个问题：

```text
这次怎么跑？
跑出来怎么样？
过程中买了什么？
```

`run_config.json` 保存本次 `Settings` 配置快照。

`performance_summary.csv` 汇总每条策略的年化收益、波动、夏普、最大回撤。

`rebalance_logs/*.csv` 保存每条策略每次调仓的日期、标的、权重、配权方式和排序。

这次升级没有新增因子，也没有接实盘。

它做的是让研究结果更可对照、可解释、可复现。

量化工程里，能跑通只是第一步。真正能迭代的结果，应该能在几周后重新打开，还知道当时发生了什么。

## 图文页脚本

1. 封面：回测跑完，还要留下实验档案  
2. 问题：只看终端和图片，过几天就忘参数

4. 新增 2：`performance_summary.csv` 保存绩效汇总  
5. 新增 3：`rebalance_logs/*.csv` 保存调仓路径  
6. 三个问题：怎么跑 / 跑得怎样 / 买了什么  
7. 代码改动：`live/cache_io.py` + `main.py`  
8. 总结：可对照、可解释、可复现
