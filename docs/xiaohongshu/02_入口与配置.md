# 02｜入口与配置：量化工程先要有一个「总开关」

**发笔记用标题（可改）：**  
量化代码｜为什么我一定要有一个 `main.py`，而不是一堆临时脚本？

---

**正文（可复制改写）**

做量化最怕什么？

不是因子公式写得不够花，而是项目慢慢长成一堆散脚本：

- 这个脚本读 CSV
- 那个脚本算 IC
- 另一个脚本画净值
- 每个脚本里还偷偷写了几个参数

最后你看到一条净值曲线，却很难回答：这次结果到底是因子变了，还是 `top_k`、手续费、调仓频率、前瞻收益口径变了？

所以这个 MVP 的第二个重点，就是把研究流程钉在两个文件上：

`main.py` 负责 **执行顺序**。  
`config.py` 负责 **实验条件**。

`main.py` 不应该塞满数学细节，它更像一个研究流水线的导演：

```text
读配置
→ 取行情数据
→ 构建四因子面板
→ 算 IC
→ 跑单因子回测
→ 做多因子融合
→ 跑融合回测
→ 算绩效
→ 输出净值 / IC / 权重图
```

这样做的好处是：你只要从一个入口跑起，就能知道整条链路有没有断。

而 `config.py` 里的 `Settings`，集中放那些会改变实验结果的东西：

```text
backtest_start / backtest_end
top_k
rebalance_freq
commission_rate
ic_forward_days
fusion_use_ic_weights
portfolio_weighting
optimizer_return_window
persist_run_outputs
```

这些参数看起来很朴素，但它们决定了一次回测的「实验条件」。

比如：

- `top_k` 改了，持仓集中度会变。
- `rebalance_freq` 改了，换手和手续费会变。
- `ic_forward_days` 改了，IC 衡量的预测窗口会变。
- `portfolio_weighting` 改了，Top-K 里的资金分配会变。
- `persist_run_outputs` 打开，行情、因子、IC、图表会落盘，方便复盘。

真正可复现的研究，不是「我记得大概怎么跑的」，而是下一次还能用同一组配置重新跑出来。

还有一个小纪律：Token 这类敏感项，不要写进要推送的仓库。这个项目里 `get_tushare_token()` 优先读环境变量 `TUSHARE_TOKEN`，本地回退只适合自己机器上临时跑通。

这一篇想表达的不是「配置文件多高级」，而是：

**量化工程的第一层秩序，是入口唯一、参数集中、结果可复现。**

**本篇讲清的量化核心点：**  
「策略逻辑」和「工程参数」分层；可复现实验从 **单一入口 + 配置可版本化** 开始。
