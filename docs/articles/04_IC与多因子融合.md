# IC 与多因子融合：先评价因子，再合成一条总得分

第三篇我们讲了数据和因子面板。

到这一步，工程里已经有了一张统一的 panel：

```text
date × symbol → MOMENTUM / VOLATILITY / PE / ROE
```

它解决的是“每一天、每只股票、每个因子得多少分”的问题。

但有了因子分数，还不能马上说这个因子有用。

一个因子至少要再过两关：

```text
第一关：它历史上有没有一点预测能力？
第二关：多个因子合在一起时，应该怎么变成一条总得分？
```

这就是第四篇要讲的两件事：

```text
IC 检验
多因子融合
```

在当前 MVP 工程里，IC 不是一个孤立的统计指标。它先用于评价因子，然后以一种很克制的方式进入融合链路：

```text
历史 IC → 滞后滚动列权 → FUSED_ZSCORE → Top-K 回测
```

注意这里的关键词是“克制”。

IC 不直接改写单因子回测，也不直接进入 Top-K 内部的最大夏普或风险平价优化。它只在多因子融合时，影响“几列因子怎么合成一列”。

这条边界，是这个 MVP 里很重要的工程纪律。

---

## 一、IC 到底在量什么？

IC 是 Information Coefficient，常见翻译是信息系数。

在因子研究里，可以先把它理解成一句话：

> 某一天，因子横截面排序和未来收益横截面排序之间的相关性。

当前工程使用的是日截面 Spearman IC。

对应代码在：

```text
analysis/ic.py
```

核心函数是：

```python
daily_ic_spearman(factor, prices_wide, forward_days=1)
```

这里有三个关键词。

### 1. 日截面

“日截面”的意思是：每个交易日单独看一组股票。

假设在某一天，有 5 只股票：

```text
000001.SZ
600036.SH
600519.SH
601318.SH
601166.SH
```

这一日，每只股票都有一个因子值，也会有一个未来收益。

IC 就在这个“同一天、不同股票”的横截面上，计算因子值和未来收益之间的相关性。

它不是在问：

```text
某只股票的因子时间序列和收益时间序列是否相关？
```

而是在问：

```text
同一天里，因子分更高的股票，未来收益排名是否也更靠前？
```

这和因子选股的直觉是一致的。

因为回测时，我们也是在调仓日做横截面排序，然后选 Top-K。

### 2. Spearman

当前工程用的是 Spearman 相关，而不是普通 Pearson 相关。

Spearman 更关注“排序关系”。

简单说，它更像在问：

```text
因子排名靠前的股票，未来收益排名是不是也靠前？
```

而不是强行要求因子值和收益值之间有线性关系。

这对因子研究很实用。

因为很多因子天然是排序信号，不一定要求“因子值多 1，收益就线性多多少”。

当前代码里，每个交易日会把有效的 `(因子值, 前瞻收益)` 配对拿出来：

```python
gg["f"].corr(gg["r"], method="spearman")
```

如果当日有效股票数太少，就记为 NaN。

默认最少有效数是：

```text
min_names = 3
```

这也是一个很小但有用的保护。

样本太少时算出来的 IC 很容易没有意义。

### 3. 前瞻收益

IC 需要比较“今天的因子”和“未来的收益”。

当前工程里的前瞻收益由：

```python
forward_returns_long(prices_wide, forward_days=1)
```

计算。

公式是：

```text
r(t, s) = close(t + h, s) / close(t, s) - 1
```

其中 `h` 就是：

```text
settings.ic_forward_days
```

默认是 1。

也就是说，默认 IC 问的是：

```text
今天因子分数较高的股票，下一交易日的收益排名是否也较高？
```

如果你把 `ic_forward_days` 改成 5，它问的问题就变成：

```text
今天因子分数较高的股票，未来 5 个交易日的收益排名是否也较高？
```

所以 IC 口径必须写清楚。

不同前瞻窗口下的 IC，不是同一个问题。

## 二、IC 结果怎么看？

当前工程会对每个默认因子计算一条日频 IC 序列。

然后用：

```python
summarize_ic(ic_ser)
```

做汇总。

输出指标包括：

```text
mean_IC
std_IC
IC_IR
hit_rate
n_days
```

可以这样理解：

### 1. mean_IC

平均 IC。

它描述的是：在有效交易日里，这个因子平均有多强的横截面预测关系。

如果长期为正，说明因子排序和未来收益排序之间有一定正相关。

但它通常不会很大。

因子研究里，稳定的小正相关也可能有价值。

### 2. std_IC

IC 的波动。

同一个因子可能有些阶段有效，有些阶段失效。

`std_IC` 越大，说明 IC 序列越不稳定。

### 3. IC_IR

IC_IR 是：

```text
mean_IC / std_IC
```

它更像是在看 IC 的稳定性。

平均值高但波动也很大，未必比平均值稍低但更稳定的因子好。

### 4. hit_rate

胜率。

当前代码里是：

```text
IC > 0 的交易日占比
```

它不是交易胜率，而是“这一天 IC 为正”的比例。

这个指标可以帮助你看因子是否经常站在正确方向上。

### 5. n_days

有效 IC 天数。

如果有效日太少，前面的统计都要谨慎看。

## 三、IC 为什么不能直接等于交易规则？

很多刚做因子研究的人，容易把 IC 理解成“有 IC 就可以买”。

这一步要小心。

IC 是评价工具，不是完整交易系统。

一个因子 IC 为正，只说明在历史样本中，因子排序和未来收益排序有一定关系。

但真正交易还要面对：

- 每次买多少只？
- 多久调一次仓？
- 交易成本是多少？
- 缺失值怎么处理？
- 持仓权重怎么分配？
- 换手率是否过高？
- 最大回撤能不能接受？

所以当前工程把 IC 和回测分开。

在 `main.py` 里，流程是：

```text
先计算每个因子的 IC
再对每个因子跑单因子回测
```

单因子回测时，IC 不参与当天选股。

它仍然是：

```text
调仓日 → 因子截面降序 → 取 Top-K → 配权 → 记净值
```

这样做有一个好处：

```text
评价归评价，交易归交易。
```

如果 IC 好但回测不好，你就要继续查：

- 是调仓频率不匹配？
- 是手续费吃掉了优势？
- 是 Top-K 太集中？
- 是因子只在某些阶段有效？
- 是因子 IC 有但收益幅度不足？

如果 IC 不好但回测很好，也要警惕：

- 是否样本太短？
- 是否某几只股票贡献了大部分收益？
- 是否有数据错位或未来函数？

IC 和回测互相补充，但不能互相替代。

## 四、多因子为什么不能直接相加？

有了四列因子之后，很自然会想：

```text
把 MOMENTUM、VOLATILITY、PE、ROE 加起来，不就得到综合分了吗？
```

问题是：它们的量纲不一样。

动量可能是：

```text
0.05
```

波动率取负后可能是：

```text
-0.20
```

PE 取负后可能是：

```text
-15
```

ROE 可能是：

```text
12.3
```

这些数字不能直接相加。

因为一个因子的数值范围更大，不代表它更重要。

直接相加会让量纲更大的列天然支配结果。

所以多因子融合的第一步，是让它们在每天的横截面上变得可比。

当前工程使用的是：

```python
cross_sectional_zscore(panel)
```

它位于：

```text
models/fusion.py
```

直觉是：对每个交易日、每一列因子，在当天股票池里做标准化：

```text
z = (x - mean) / std
```

这样每个因子每天都变成相对分数。

此时你比较的不再是原始单位，而是：

```text
这只股票在这个因子上，相对当天其他股票高多少。
```

这就是横截面 z-score。

## 五、等权 z-score 融合

最简单的融合方式是等权。

当前工程里对应：

```python
fuse_equal_weight_zscore(panel)
```

逻辑是：

```text
先做横截面 z-score
再对多列因子取平均
```

也就是：

```text
FUSED = mean(z_MOMENTUM, z_VOLATILITY, z_PE, z_ROE)
```

这会得到一列综合得分。

它和单因子一样，也是：

```text
MultiIndex(date, symbol) → score
```

后面可以直接交给回测：

```text
调仓日 → FUSED 降序 → Top-K → 配权 → 净值
```

等权融合的优点是简单、透明、稳定。

它的缺点是：默认每个因子永远同等重要。

如果某个阶段动量明显更有效，估值明显失效，等权不会自动调整。

所以当前 MVP 又提供了一个稍微动态一点的版本：

```text
IC 滞后滚动列权融合
```

## 六、IC 滞后滚动列权融合

当前主流程默认使用：

```python
fuse_ic_weighted_zscore(panel, ic_by_factor)
```

它的完整思路是：

```text
1. 每列因子先做横截面 z-score
2. 每列因子都有一条历史日频 IC
3. 对 IC 先 shift(1)，再 rolling 求均值
4. 把滚动均值中为正的部分归一化成列权
5. 按列权加权求和，得到 FUSED_ZSCORE
```

写成一句话就是：

```text
近期 IC 更好的因子，在综合分里说话更多。
```

这里最重要的细节是：

```text
shift(1)
```

也就是今天用于融合的权重，只能依赖昨天及更早的 IC。

为什么？

因为当天 IC 需要当天之后的前瞻收益才能知道。

如果你用当天 IC 来决定当天的融合权重，就会偷看未来。

当前代码里先做：

```python
ic_s.shift(1).rolling(...)
```

这就是为了避免这种前视偏差。

---

## 七、列权为什么要非负归一？

`fuse_ic_weighted_zscore` 里还有一个细节：

```python
raw = np.maximum(row.to_numpy(dtype=float), 0.0)
```

也就是说，历史滚动 IC 为负的因子，当天列权会被压到 0。

然后再把所有正权重归一化，让它们加起来等于 1。

如果当天所有因子的滚动 IC 都不是正的，或者样本不足，就回退等权。

这个设计的直觉是：

```text
最近评价为正的因子参与融合。
最近评价不好的因子少说话或不说话。
如果没法判断，就回到等权。
```

这不是最复杂的动态模型。

但它适合 MVP。

因为它同时满足几个条件：

- 逻辑透明。
- 不需要训练复杂模型。
- 能和等权融合作对照。
- 权重来自历史 IC，避免直接偷看未来。
- 失败时可以回退等权，不让主流程中断。

## 八、IC 在本项目里到底进入了哪里？

这一点要说清楚。

在当前 MVP 中，IC 有两个位置。

第一个位置是评价：

```text
每个因子 → 日频 IC → mean_IC / IC_IR / 胜率
```

第二个位置是融合：

```text
各因子历史 IC → 滞后滚动列权 → FUSED_ZSCORE
```

它没有进入两个地方。

第一，它不改变单因子回测。

单因子回测仍然只用对应那一列因子排序。

第二，它不进入 Top-K 内的组合配权优化。

当前的最大夏普和风险平价配权，只发生在已经选出的 Top-K 股票内部，使用的是历史收益均值和协方差。

IC 不会直接写入这里的 μ 或 Σ。

所以当前工程的分层是：

```text
IC：评价因子，并影响多因子列权
因子 / FUSED 得分：负责选股排序
组合优化：负责 Top-K 内部资金比例
回测：负责交易规则、手续费和净值
```

这条边界能防止系统变成一锅粥。

---

## 九、FUSED_ZSCORE 最后怎么参与回测？

在 `main.py` 中，融合逻辑大致是：

```text
取 panel 中的四列默认因子
根据配置决定 IC 加权或等权融合
得到 fused
调用 run_multi_backtest(fused=..., factor_name="FUSED_ZSCORE")
```

`run_multi_backtest` 最终还是会把这列综合得分交给单因子回测逻辑。

也就是说，融合策略并没有发明一套新的交易规则。

它仍然走同一套：

```text
调仓日 → FUSED_ZSCORE 降序 → Top-K → 配权 → 扣手续费 → 生成净值
```

这样做的好处是：你能公平比较。

单因子和融合策略之间，差异主要来自“选股得分列不同”，而不是每条曲线偷偷用了不同的回测规则。

最终你可以同时看到：

- MOMENTUM 的 IC 和净值
- VOLATILITY 的 IC 和净值
- PE 的 IC 和净值
- ROE 的 IC 和净值
- FUSED_ZSCORE 的 IC 和净值

这就是一个最小但完整的因子研究对照台。

## 十、这篇文章的核心结论

IC 和多因子融合解决的是两个连续问题。

IC 先问：

```text
这些因子历史上有没有一点预测味？
```

融合再问：

```text
如果多个因子都能给股票打分，怎样合成一条总得分？
```

当前 MVP 的答案是：

```text
先用 Spearman IC 做横截面评价。
再用横截面 z-score 统一量纲。
最后用等权或 IC 滞后滚动列权合成 FUSED_ZSCORE。
```

最重要的工程纪律是：

```text
IC 不直接等于交易。
融合不改变回测规则。
所有权重都必须来自当时已经可见的信息。
```

这样，系统既能让 IC 从“只看不管”的指标进入一点决策，又不会让评价、选股、配权和回测混成一团。
