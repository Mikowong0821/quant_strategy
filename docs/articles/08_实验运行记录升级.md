# 实验运行记录升级：让每次回测都留下可复查档案

前面几篇文章一直在强调一件事：

```text
量化研究要可对照、可解释、可复现。
```

但只靠终端打印和几张图，还不够。

因为过几天以后，你很可能会忘记：

- 当时 `top_k` 是多少？
- 用的是等权、最大夏普，还是风险平价？
- 手续费率是多少？
- IC 前瞻天数是多少？
- 融合是否用了 IC 滞后滚动列权？
- 每条策略最后的绩效指标分别是多少？
- 某一期到底选了哪些股票、权重是多少？

所以这次我们给 MVP 补了一层很实际的能力：

```text
实验运行记录落盘。
```

它不改变策略逻辑，不改变因子，不改变回测规则。

它做的是把一次运行的关键上下文结构化保存下来。

---

## 一、这次新增了什么？

这次主要新增三类输出。

### 1. 配置快照

路径：

```text
output/cache/run_config.json
```

它保存本次运行用到的 `Settings`。

包括：

- `backtest_start`
- `backtest_end`
- `top_k`
- `rebalance_freq`
- `commission_rate`
- `portfolio_weighting`
- `ic_forward_days`
- `fusion_use_ic_weights`
- `optimizer_return_window`
- `optimizer_min_obs`
- `data_dir`
- `output_dir`

这样以后看到一张图，不用猜当时怎么跑的。

### 2. 绩效汇总

路径：

```text
output/performance_summary.csv
```

它把每条策略的绩效放到一张表里：

```text
strategy
ann_return
ann_vol
sharpe
max_drawdown
```

比如：

```text
MOMENTUM
VOLATILITY
PE
ROE
FUSED_ZSCORE
```

以后比较单因子和融合策略，不需要从终端输出里翻。

### 3. 调仓日志

路径：

```text
output/rebalance_logs/<strategy>.csv
```

每条策略一份 CSV。

列包括：

```text
date
symbol
weight
weighting
rank
```

它回答的是：

```text
某一天调仓时，这条策略选了哪些股票？
每只权重是多少？
当期用的是等权、最大夏普、风险平价，还是回退等权？
```

这比只看净值曲线更接近真实研究记录。

---

## 二、代码改在哪里？

主要改动在：

```text
live/cache_io.py
main.py
```

`live/cache_io.py` 新增了几个函数：

```python
settings_to_dict(settings)
save_run_config(settings)
save_performance_summary(settings, performance_by_name)
save_rebalance_logs(settings, meta_by_name)
```

`main.py` 负责在回测完成后收集：

```text
performance_by_name
backtest_meta_by_name
```

然后在 `persist_run_outputs=True` 时统一写出：

```text
run_config.json
performance_summary.csv
rebalance_logs/*.csv
```

这样 `main.py` 仍然只做编排，具体落盘格式留在 `cache_io` 里。

---

## 三、为什么这一步很值？

因为它补上了 MVP 研究闭环里很关键的一环：

```text
实验档案。
```

以前的输出更偏：

```text
看图
看终端
看缓存
```

现在可以更明确地对照：

```text
这次参数是什么？
这次每条策略成绩如何？
这次每期持仓路径是什么？
```

这对后续文章、复盘、调参都很有用。

比如你把 `portfolio_weighting` 从：

```text
max_sharpe
```

改成：

```text
risk_parity
```

跑完以后可以直接对比：

```text
performance_summary.csv
rebalance_logs/FUSED_ZSCORE.csv
weights_FUSED_ZSCORE.png
```

这样你看到的不只是“净值变了”，而是知道它为什么可能变了。

---

## 四、这次没有做什么？

这次没有做：

- 新因子
- 新融合模型
- 新优化器
- 实盘接口
- 数据库实验追踪
- Web 可视化面板

原因很简单：

当前 MVP 更需要的是把现有运行结果记录清楚，而不是继续堆复杂度。

真正专业的量化工程，不是功能越多越好。

而是每次运行都能回答：

```text
我用什么条件跑的？
我得到了什么结果？
我能不能回看细节？
我能不能和下一次对照？
```

## 五、验证结果

新增了单元测试：

```text
tests/test_cache_io.py
```

验证：

- `run_config.json` 能写出配置快照。
- `performance_summary.csv` 能写出绩效表。
- `rebalance_logs/*.csv` 能写出调仓明细。

同时跑了相关测试：

```bash
python3 -m unittest tests.test_cache_io tests.test_plotting tests.test_backtest_single -v
```

结果通过。

测试过程中 Matplotlib 提示本机缓存目录不可写，自动使用了临时目录；这不影响测试结果。

---

## 七、总结

这次升级的核心不是“让策略更赚钱”。

它是让研究过程更可靠。

新增的三个文件族：

```text
run_config.json
performance_summary.csv
rebalance_logs/*.csv
```

分别解决：

```text
这次怎么跑？
跑出来怎么样？
过程中买了什么？
```

这正好对应量化 MVP 最重要的三件事：

```text
可对照
可解释
可复现
```

下一步如果继续加厚，可以考虑把 `run_config.json` 扩展成完整实验元数据，加入 git commit、依赖版本、运行耗时和实验编号。
