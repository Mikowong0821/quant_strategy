# 绩效、图表与复现：把净值曲线变成可对照的实验记录

第五篇我们讲了回测和组合配权。

到这一步，系统已经能把一列因子分数或融合得分，翻译成一条净值曲线：

```text
得分 → Top-K → 配权 → 调仓 → 手续费 → 净值
```

但一条净值曲线还不是完整的研究结论。

你还要继续回答：

```text
这条曲线的收益和风险如何？
最大回撤有多深？
和其他因子相比强在哪里？
IC 是否阶段性失效？
权重是否过度集中？
这次结果以后能不能复现？
```

这就是第六篇要讲的主题：

```text
绩效、图表与复现
```

当前 MVP 工程里，输出层主要由三块组成：

```text
analysis/performance.py：绩效指标
analysis/plotting.py：净值、IC、权重图
live/cache_io.py：运行缓存落盘
```

它们的作用不是“装饰结果”，而是把一次回测变成可解释、可对照、可复查的实验记录。

---

## 一、为什么不能只看净值曲线？

很多人看回测，第一眼只看净值线。

如果曲线一路向上，就觉得策略不错。

如果曲线震荡很大，就觉得策略不好。

但这不够。

同样是期末净值 1.3，两条策略可能完全不同：

```text
策略 A：一路平稳上涨，最大回撤很小。
策略 B：中间腰斩过一次，最后靠少数几天拉回来。
```

如果只看期末值，你会把它们误认为差不多。

所以绩效层要把净值曲线拆成几个更具体的问题：

- 年化收益是多少？
- 年化波动是多少？
- 单位波动换来了多少收益？
- 最大回撤有多深？
- IC 是否支持这条收益曲线？
- 权重是否集中在少数股票上？

绩效和图表的意义，就是把一条曲线拆开看。

---

## 二、绩效指标从哪里来？

当前项目的绩效函数在：

```text
analysis/performance.py
```

核心函数是：

```python
summarize(nav, risk_free=0.0, periods=252)
```

输入是回测输出的日频净值序列：

```text
nav
```

输出是一个字典：

```text
ann_return
ann_vol
sharpe
max_drawdown
```

这些指标都只描述这一条已经实现的净值曲线。

这点要和第五篇里的“最大夏普配权”区分开。

第五篇里的最大夏普，是调仓时用 Top-K 股票的历史收益和协方差估出来的目标权重。

这里的夏普，是回测结束以后，用整条净值曲线算出来的成绩单。

名字相似，但层级不同：

```text
配权夏普：调仓时的优化目标。
绩效夏普：回测后的结果描述。
```

---

## 三、年化收益：把样本期收益换算成年口径

当前代码里，年化收益的计算逻辑是：

```python
ann_return = (nav.iloc[-1] / nav.iloc[0]) ** (periods / max(n - 1, 1)) - 1
```

直觉是：

```text
把样本期净值涨幅，按交易日数量折算成年化。
```

其中：

```text
periods = settings.trading_days_per_year
```

默认是 252。

这个指标回答的是：

```text
如果这段样本里的复合增长节奏延续一年，大约是多少年化收益？
```

但要注意，它只是研究常用的简化口径。

样本很短时，年化收益会非常敏感。

比如只跑几十个交易日，某几天涨跌就可能让年化结果看起来很夸张。

所以年化收益不能单独看。

---

## 四、年化波动：净值每天抖得有多厉害

代码里先从净值算日收益：

```python
ret = nav.pct_change().fillna(0.0)
```

然后计算年化波动：

```python
ann_vol = ret.std() * sqrt(periods)
```

它描述的是：

```text
这条净值曲线每天波动有多大，折算成年口径是多少。
```

年化收益高但波动也高，不一定是更好的策略。

你要看它为了收益承担了多少波动。

这就引出下一个指标：

```text
Sharpe
```

---

## 五、夏普比率：单位波动换来多少收益

当前绩效层的夏普计算是：

```python
sharpe = (ann_return - risk_free) / ann_vol
```

默认：

```text
risk_free = 0.0
```

所以它大致表达：

```text
每承担一单位年化波动，换来多少年化收益。
```

夏普是一个很常见的策略比较指标。

但它也有局限。

它把波动当作主要风险，却不直接告诉你：

- 回撤发生在哪里？
- 最大亏损持续多久？
- 是否有尾部极端损失？
- 收益是否来自少数几天？

所以夏普也不能单独看。

它必须和最大回撤、净值图、权重图一起看。

---

## 六、最大回撤：从高点到低点最痛的一段

最大回撤在代码里是这样算的：

```python
cum = (1 + ret).cumprod()
peak = cum.cummax()
dd = cum / peak - 1
max_drawdown = dd.min()
```

直觉是：

```text
每一天都看当前净值相对历史最高点跌了多少。
```

最大回撤就是这条回撤序列里最深的那个点。

它回答的是：

```text
如果你在历史高点买入，最难受的时候账面亏了多少？
```

这对策略体验非常重要。

很多策略年化收益看起来不错，但最大回撤太深，真实执行时很难坚持。

所以绩效层至少要同时看：

```text
收益
波动
夏普
回撤
```

它们描述的是同一条净值曲线的不同侧面。

## 七、图表一：净值对比图

图表层在：

```text
analysis/plotting.py
```

净值图函数是：

```python
plot_nav(...)
```

`main.py` 会把各条曲线收集到：

```text
nav_curves
```

最后保存：

```text
output/nav_compare.png
```

默认情况下，图会做归一化：

```text
每条曲线除以自己的起点
```

这样不同策略可以从相同起点比较形态。

这张图主要用来回答：

- 哪条因子曲线更平稳？
- 融合曲线是否比单因子更稳？
- 策略之间的回撤是否同步？
- 某些阶段是否集体失效？

净值对比图是最直观的图，但它不是唯一证据。

---

## 八、图表二：IC 图

IC 图也在：

```python
plot_ic(...)
```

`main.py` 会在开启落盘时输出：

```text
output/ic_compare.png
output/ic_timeseries_*.png
```

IC 图回答的是：

```text
因子的预测关系是否稳定？
```

如果一条策略净值不错，但 IC 长期贴近 0 或剧烈反转，就要小心。

可能是样本太短。

可能是少数股票贡献了大部分收益。

也可能是回测规则和因子评价之间存在不一致。

单因子 IC 图还可以叠加滚动均值。

这比只看一个 mean_IC 更直观，因为它能看到阶段性变化。

因子不是永远有效的。

IC 图的意义，就是提醒你不要把一段历史里的表现当成永久规律。

---

## 九、图表三：权重图

第五篇讲过，每次调仓都会留下：

```text
meta["rebalance_log"]
```

图表层可以用：

```python
rebalance_log_to_weights_frame(...)
```

把调仓日志转成：

```text
再平衡日 × 标的
```

的权重宽表。

再用：

```python
plot_weights(...)
```

保存权重图：

```text
output/weights_*.png
```

权重图回答的是：

- 持仓是否过度集中？
- 权重是否频繁漂移？
- 某只股票是否长期占据大头？
- 优化配权是否比等权更极端？
- 回退等权的时期是否明显？

很多时候，净值图看不出仓位结构。

权重图能告诉你：

```text
这条净值曲线背后，到底是怎样的持仓路径。
```

这对排错和风险控制都很重要。

## 十、为什么要落盘？

如果 `settings.persist_run_outputs` 打开，当前项目会把一批结果写到 `output/` 目录。

缓存逻辑在：

```text
live/cache_io.py
```

`save_run_cache(...)` 会写入：

```text
output/cache/prices_long.csv
output/cache/prices_wide_close.csv
output/cache/factor_panel.csv
output/cache/run_meta.txt
```

IC 序列也会写到：

```text
output/cache/ic_<name>.csv
```

现在主流程还会额外保存三类实验记录：

```text
output/cache/run_config.json
output/performance_summary.csv
output/rebalance_logs/<strategy>.csv
```

它们分别记录本次配置快照、各策略绩效汇总、以及每条策略逐次调仓的标的和权重。

后续基准模块加入后，`performance_summary.csv` 还会包含相对股票池等权基准的超额收益、跟踪误差和信息比率，主流程也会额外输出：

```text
output/excess_nav_compare.png
```

换手模块加入后，`performance_summary.csv` 还会包含 `avg_turnover`、`total_turnover`、`estimated_total_cost` 等字段，并额外输出：

```text
output/turnover_logs/<strategy>.csv
output/turnover_compare.png
```

这些文件不是为了“多存点东西”。

它们的价值是复现。

你以后看到一张净值图时，应该能回头确认：

- 当时用的是哪段行情？
- 因子面板长什么样？
- IC 序列是什么？
- 回测区间是什么？
- 价格列是什么？
- 图是从哪次运行来的？

如果没有落盘，很多研究结果会变成“我记得当时跑出来是这样”。

这在量化里不够。

研究需要能回放。

## 十一、run_meta 记录了什么？

当前 `run_meta.txt` 会记录：

```text
written_utc
backtest_start
backtest_end
price_col
```

这只是一个很小的元数据文件。

更完整的配置快照会写到：

```text
output/cache/run_config.json
```

它会把 `Settings` 中的路径、回测区间、`top_k`、手续费、调仓频率、IC 前瞻天数、融合开关、配权方式等一起保存下来。

但它代表了一个方向：

```text
每次运行都应该留下实验条件。
```

未来如果要继续演进，可以把更多配置写进去：

- `top_k`
- `rebalance_freq`
- `commission_rate`
- `portfolio_weighting`
- `ic_forward_days`
- `fusion_use_ic_weights`
- `optimizer_return_window`

甚至可以加上 git commit、运行时间、依赖版本。

MVP 阶段先记录最基本的运行信息。

后面逐步把它扩展成实验追踪系统。

---

## 十二、这篇文章的核心结论

绩效、图表和落盘，不是研究结束后的装饰。

它们是量化工程的输出契约。

当前 MVP 的输出层可以概括为：

```text
performance：把净值变成年化、波动、夏普、回撤
benchmark：构造股票池等权基准并计算超额收益指标
turnover：从调仓日志计算换手率和预估交易成本
performance_summary.csv：保存各策略绩效汇总、相对基准指标和换手成本指标
rebalance_logs/*.csv：保存每条策略调仓路径
turnover_logs/*.csv：保存每条策略逐期换手路径
run_config.json：保存本次配置快照
plot_nav：比较单因子、融合和基准净值，也用于画超额净值
plot_turnover：比较各策略逐期换手率
plot_ic：观察因子预测关系是否稳定
plot_weights：检查持仓权重路径
cache_io：把行情、因子、IC 和元数据落盘
```

一条策略不能只靠“净值好看”来说服自己。

你至少要同时看到：

```text
收益风险指标
净值形态
IC 稳定性
权重结构
可复现文件
```

这样一次回测才从“跑出一张图”，变成“留下一个可以被复查的实验”。
