# 换手率与交易成本：收益不是白来的

前面第 9 篇我们补了基准与超额收益。

它解决的问题是：

```text
策略到底有没有跑赢一个合理的参照组？
```

但即使策略跑赢了基准，还不能马上说它就有实盘价值。

因为还要继续问一个更接近真实交易的问题：

```text
这些收益，是用多高的换手换来的？
```

所以这次我们给 Quant Strategy MVP 补了新模块：

```text
analysis/turnover.py
```

它不改变因子，不改变选股，不改变回测撮合。

它做的是：

```text
从调仓日志里还原每期目标权重变化，
估算换手率和交易成本压力。
```

这一步很重要。

因为策略回测看起来赚钱，不代表交易之后还能留下同样多的收益。

高换手策略在回测里可能很漂亮，但一旦考虑手续费、滑点、冲击成本，净值可能明显缩水。

---

## 一、为什么要看换手率？

假设有两条策略。

策略 A：

```text
年化收益：18%
年化超额：6%
平均每月换手：0.3
```

策略 B：

```text
年化收益：22%
年化超额：8%
平均每月换手：2.5
```

只看收益，策略 B 更好。

但如果策略 B 每个月都在大幅换仓，那么它对交易成本会非常敏感。

只要手续费、滑点、冲击成本稍微高一点，策略 B 的优势可能就被吃掉。

这就是换手率要回答的问题：

```text
策略为了获得这些收益，到底交易得有多频繁？
```

在量化研究里，收益不是孤立存在的。

至少要和三个东西一起看：

```text
收益
风险
交易成本
```

前面我们已经有：

```text
收益：ann_return / excess_ann_return
风险：ann_vol / max_drawdown / tracking_error
```

现在补：

```text
交易成本压力：turnover / estimated_cost
```

这样研究结果才更接近真实世界。

---

## 二、什么是 turnover？

`turnover` 一般翻译成换手率。

在组合回测里，它通常描述：

```text
这一次调仓，组合里有多少资金发生了交易。
```

这次 MVP 里的定义很明确：

```text
turnover = sum(abs(current_weight - previous_weight))
```

也就是：

```text
本期目标权重相对上期目标权重的绝对变化和
```

举个简单例子。

上一期持仓：

```text
A: 60%
B: 40%
```

这一期目标持仓：

```text
B: 50%
C: 50%
```

那么：

```text
A: 60% → 0%   变化 60%
B: 40% → 50%  变化 10%
C: 0%  → 50%  变化 50%
```

所以：

```text
turnover = 0.6 + 0.1 + 0.5 = 1.2
```

含义是：

```text
这次调仓的成交金额大约是组合净值的 120%。
```

注意这里的 turnover 不是“换掉了几只股票”，而是看资金权重变化。

同样换两只股票，如果权重变化很小，换手也可能不高。

---

## 三、为什么初次建仓通常是 1.0？

如果上一期没有持仓，也就是现金状态：

```text
上一期：
空仓
```

本期目标持仓：

```text
A: 60%
B: 40%
```

那么：

```text
A: 0% → 60%  变化 60%
B: 0% → 40%  变化 40%
```

所以：

```text
turnover = 1.0
```

这表示：

```text
从现金买入到满仓，成交金额大约等于组合净值。
```

这和直觉一致。

初次建仓不是免费发生的。

它也要产生交易成本。

---

## 四、estimated_cost 怎么算？

当前配置里已经有：

```text
commission_rate
```

也就是单边手续费率。

这次换手模块会估算：

```text
estimated_cost = turnover * commission_rate
```

比如：

```text
turnover = 1.2
commission_rate = 0.0003
```

那么：

```text
estimated_cost = 1.2 * 0.0003 = 0.00036
```

也就是大约：

```text
0.036%
```

这不是完整实盘成本。

因为真实交易还可能有：

- 印花税
- 滑点
- 冲击成本
- 最小交易单位
- 停牌与涨跌停约束
- 成交量容量限制

但在 MVP 阶段，先用手续费率估一个最低成本压力，是很有意义的。

它至少能帮我们识别：

```text
哪条策略天然换手很高；
哪条策略对成本更敏感；
哪条策略的收益可能被交易成本吃掉。
```

## 五、为什么从 rebalance_log 计算？

这次没有直接改回测撮合核心。

而是复用已有的：

```text
meta["rebalance_log"]
```

它里面已经记录了每次调仓的：

```text
date
picks
weights
weighting
```

也就是：

```text
哪天调仓
买了哪些股票
目标权重是多少
使用了什么配权方式
```

换手率本质上就是比较：

```text
上一期目标权重
vs
本期目标权重
```

所以 `rebalance_log` 正好是最自然的输入。

这也符合工程分层：

```text
backtest：负责生成交易路径和净值
turnover：负责解释交易路径的换手与成本
```

换手模块不应该反过来影响选股或调仓。

它只是分析层。

## 六、这次新增了哪些指标？

在：

```text
output/performance_summary.csv
```

里，每条策略会多出几列：

```text
avg_turnover
max_turnover
total_turnover
estimated_total_cost
n_turnover_periods
```

分别是什么意思？

### 1. avg_turnover

平均每次调仓换手率。

它回答：

```text
这条策略每次调仓平均要交易多少组合净值？
```

如果 `avg_turnover = 0.4`，说明平均每次调仓大约交易组合净值的 40%。

如果 `avg_turnover = 1.5`，说明平均每次调仓成交金额超过组合净值。

这通常意味着持仓变化很剧烈。

### 2. max_turnover

单次最大换手率。

它回答：

```text
有没有某一期发生特别剧烈的换仓？
```

有些策略平均换手不高，但某几期换手突然很大。

这可能来自：

- 因子排序突然变化
- 股票池数据缺失
- 配权方式大幅改变
- 某些股票退出 Top-K

所以 `max_turnover` 可以帮我们定位异常调仓。

### 3. total_turnover

整个回测期间累计换手。

它回答：

```text
这条策略总共交易了多少组合净值？
```

如果回测一年，`total_turnover = 12`，大致可以理解为：

```text
全年累计成交金额约为组合净值的 12 倍。
```

这对成本非常敏感。

### 4. estimated_total_cost

预估累计交易成本。

计算方式：

```text
estimated_total_cost = sum(turnover * commission_rate)
```

它回答：

```text
仅按手续费估算，这条策略大约损失了多少净值比例？
```

注意它只是估算，不是券商对账单。

但它足够作为 MVP 阶段的成本压力指标。

### 5. n_turnover_periods

参与统计的调仓次数。

它回答：

```text
这条策略实际发生了多少次有效调仓？
```

如果某条策略调仓次数明显少于其他策略，说明因子缺失、价格缺失或调仓日有效截面可能不一样。

## 七、新增的输出文件

这次新增两类输出。

### 1. 换手日志

路径：

```text

```

比如：

```text

output/turnover_logs/FUSED_ZSCORE.csv
```

每个文件包含：

```text

```

它和：

```text

```

互相补充。

`rebalance_logs` 记录：

```text

```

`turnover_logs` 记录：

```text
这次调仓变化有多大、估算成本是多少
```

### 2. 换手图

路径：

```text
output/turnover_compare.png
```

它会把多条策略的逐期换手率画在一张图上。

这张图适合看：

```text
哪条策略长期高换手；
哪条策略某一期突然大幅换仓；
融合策略是否比单因子更稳定；
最大夏普或风险平价是否导致权重频繁变化。
```

## 十、换手率怎么读？

读换手率时，不要只看一个字段。

建议结合看：

```text
ann_return
excess_ann_return
information_ratio
avg_turnover
total_turnover
estimated_total_cost
max_drawdown
```

比如：

### 情况 1：高收益 + 低换手

这是比较理想的。

说明策略没有依赖频繁交易，也能产生收益。

当然，还要继续看容量、风控和样本外。

### 情况 2：高收益 + 高换手

要谨慎。

它可能是有效的短周期信号，也可能只是回测里没充分计入成本。

下一步需要补：

```text
滑点
冲击成本
成交量约束
```

### 情况 3：低收益 + 高换手

这通常不太好。

说明策略既没赚到钱，又频繁交易。

这种策略很容易被成本进一步拉低。

### 情况 4：低收益 + 低换手

至少成本压力不大。

但如果超额收益也低，那说明因子本身可能不够强。

## 十一、它和回测里的手续费有什么区别？

当前回测撮合里已经会扣：

```text
commission_rate
```

那为什么还要单独做 `estimated_cost`？

因为两者用途不一样。

回测里的手续费是：

```text
影响净值计算的交易成本。
```

换手模块里的 `estimated_cost` 是：

```text
用于研究解释和横向比较的成本压力指标。
```

前者用于算净值。

后者用于看策略特征。

比如两条策略净值都差不多，但一条策略累计换手是 3，另一条是 20。

这两条策略的实盘可信度显然不一样。

即使回测已经扣过手续费，研究表里仍然需要把换手和成本压力单独列出来。

## 十二、这一步的工程意义

这次升级让 MVP 的研究输出更完整。

之前我们能回答：

```text
策略赚了多少？
相对基准赚了多少？
风险和回撤怎么样？
每期买了什么？
```

现在还能回答：

```text
策略为了这些收益交易了多少？
成本压力大不大？
是否存在异常换仓？
哪条策略更接近可交易？
```

这就是从“看净值”走向“看交易质量”。

一个策略如果只能在零成本、无限流动性、频繁换仓假设下好看，那么它离真实世界还很远。

换手率和交易成本分析，就是把策略往真实世界拉近的一步。

---

## 十三、下一步可以怎么继续？

这次只是 MVP 版本。

后续可以继续补：

```text
滑点模型
印花税
成交量容量约束
涨跌停无法成交
停牌处理
换手拆分为买入换手 / 卖出换手
行业或市值暴露变化
```

但我不建议一上来就把这些全塞进去。

更合理的顺序是：

```text
先把目标权重变化和成本压力记录下来，
再逐步加真实交易约束。
```

这符合我们一直在做的 MVP 思路：

```text
先让链路清楚、可复现、可对照，
再逐层提高真实度。
```
