# 基准与超额收益：策略到底赢在哪里？

前面我们已经把 Quant Strategy MVP 跑成了一条完整链路：

```text
数据 → 因子面板 → IC → 回测 → 组合配权 → 绩效图表 → 实验记录落盘
```

这已经能回答很多问题：

- 因子有没有一定预测能力？
- 单因子和融合因子谁表现更好？
- 每次调仓买了什么？
- 最大回撤、夏普、年化收益是多少？
- 这次实验配置能不能复现？

但还差一个量化研究里非常关键的问题：

```text
策略赚的钱，到底是策略自己赚的，还是市场/股票池整体涨出来的？
```

所以这次我们给 MVP 加了一个新模块：

```text
analysis/benchmark.py
```

它负责做两件事：

```text
1. 构造基准净值
2. 计算策略相对基准的超额收益指标
```

这一步看起来不复杂，但它会明显提高整个研究框架的判断质量。

因为量化研究不能只问：

```text
策略有没有赚钱？
```

还要问：

```text
策略有没有跑赢一个合理的对照组？
```

---

## 一、为什么要加基准？

假设某条策略回测出来：

```text
年化收益：18%
最大回撤：-12%
夏普：1.1
```

只看这组数字，好像还不错。

但如果同一时期股票池整体等权上涨了 25%，那这个策略其实并不强。

它不是“赚了 18%”，而是：

```text
在一个整体涨 25% 的环境里，只赚了 18%。
```

换句话说，它相对股票池是落后的。

反过来，如果某条策略绝对收益只有 6%，但同一时期股票池整体跌了 15%，那么它反而可能很有价值。

因为它的意义不是“赚了 6%”，而是：

```text
在整体下跌环境里，仍然守住了净值，并且跑赢了基准。
```

这就是基准的作用。

它给策略找一个参照物。

没有基准时，净值曲线很容易让人误判：

- 牛市里，很多策略都会赚钱。
- 熊市里，很多策略都会亏钱。
- 震荡市里，绝对收益可能不高，但相对收益可能很稳定。

所以策略研究不能只看“绝对净值”，还要看“相对净值”。

---

## 二、什么是 benchmark？

`benchmark` 就是基准。

在投资里，它代表一条参照曲线。

常见基准可以是：

- 沪深 300
- 中证 500
- 中证 1000
- 行业指数
- 股票池等权组合
- 自定义可投资 universe 的平均表现

这次 MVP 里，我们没有直接接外部指数，而是先做了一个更工程友好的基准：

```text
股票池等权基准
```

也就是：

```text
每天持有当前价格宽表里的所有股票；
每天按所有股票的日收益做等权平均；
再把这个平均收益累乘成一条净值曲线。
```

它在代码里叫：

```text
BENCH_EQUAL_WEIGHT
```

为什么先用股票池等权，而不是直接用沪深 300？

因为这个 MVP 当前的策略是在一个内部股票池里选 Top-K。

如果策略只在这几只股票里选，那么最直接的对照组就是：

```text
不选股，直接把这个股票池等权买下来。
```

这能回答一个非常重要的问题：

```text
我的因子选股是否比“无脑等权持有整个股票池”更好？
```

这个问题比“有没有跑赢沪深 300”更贴近当前工程。

因为如果股票池本身不是沪深 300 成分，那么拿沪深 300 当基准可能会混入风格、行业、市值暴露差异。

而股票池等权基准至少保证了一个前提：

```text
策略和基准面对的是同一个股票池。
```

---

## 三、股票池等权基准怎么计算？

新增模块：

```text
analysis/benchmark.py
```

核心函数：

```python
equal_weight_benchmark_nav(prices)
```

它的输入是价格宽表：

```text
行：交易日
列：股票代码
值：收盘价
```

示意：

```text
date        600519.SH   000001.SZ   601318.SH
2024-01-02  100.0       10.0        50.0
2024-01-03  101.0       10.1        49.5
2024-01-04  102.0       10.0        50.5
```

第一步，计算每只股票的日收益：

```text
ret_i,t = close_i,t / close_i,t-1 - 1
```

第二步，对当日所有可用股票收益做平均：

```text
benchmark_ret_t = mean(ret_i,t)
```

第三步，把日收益累乘成净值：

```text
benchmark_nav_t = ∏(1 + benchmark_ret_t)
```

这条净值就是：

```text
BENCH_EQUAL_WEIGHT
```

在 `main.py` 中，它会和单因子策略、融合策略放到同一张净值图里：

```text
output/nav_compare.png
```

这样你就能看到：

```text
MOMENTUM
VOLATILITY
PE
ROE
FUSED_ZSCORE
BENCH_EQUAL_WEIGHT
```

谁是真的跑得更好。

## 四、什么是超额收益？

有了基准之后，我们就可以计算：

```text
策略收益 - 基准收益
```

这就是超额收益，也叫主动收益。

在代码里，我们用日收益来算：

```text
active_return_t = strategy_return_t - benchmark_return_t
```

如果某天策略涨 1.2%，基准涨 0.7%，那么当天超额收益是：

```text
0.5%
```

如果某天策略跌 0.3%，基准涨 0.4%，那么当天超额收益是：

```text
-0.7%
```

超额收益的意义是：

```text
把市场/股票池整体涨跌先扣掉，再看策略自己的贡献。
```

这一步非常重要。

因为绝对收益会同时包含两部分：

```text
绝对收益 = 基准收益 + 超额收益
```

其中：

- 基准收益：股票池整体涨跌带来的部分。
- 超额收益：因子选股、组合配权、调仓规则带来的相对表现。

量化研究更关心后者。

因为市场涨跌不是策略真正能稳定控制的东西。

策略真正要证明的是：

```text
我能否在同一个可投资范围里，稳定选得比平均更好。
```

## 五、超额净值图有什么用？

这次新增输出：

```text
output/excess_nav_compare.png
```

它画的是每条策略相对基准的超额净值。

简单理解：

```text
如果超额净值向上，说明策略持续跑赢基准。
如果超额净值横着走，说明策略和基准差不多。
如果超额净值向下，说明策略长期跑输基准。
```

这张图有时候比普通净值图更重要。

比如普通净值图里，所有曲线都在上涨。

你可能会觉得：

```text
这些策略都还行。
```

但超额净值图可能告诉你：

```text
只有 FUSED_ZSCORE 在持续跑赢基准；
其他单因子只是跟着股票池一起涨。
```

这就是超额净值图的价值。

它能把“市场给的收益”和“策略自己的收益”分开看。

## 六、tracking error 是什么？

`tracking error` 通常翻译成跟踪误差。

在这里，它不是“程序出错”的误差。

它衡量的是：

```text
策略相对基准的主动收益有多波动。
```

计算上，它是主动收益的年化波动率：

```text
tracking_error = std(active_return) × sqrt(252)
```

如果 tracking error 很低，说明策略走势和基准很接近。

如果 tracking error 很高，说明策略相对基准偏离很大。

偏离大不一定是坏事。

关键要看偏离是否带来了稳定的正超额。

比如：

```text
策略 A：年化超额 5%，tracking error 3%
策略 B：年化超额 8%，tracking error 20%
```

策略 B 的超额更高，但波动也大很多。

这时不能只看 `excess_ann_return`。

还要看下一项：

```text
information_ratio
```

## 七、information ratio 是什么？

`information ratio` 通常叫信息比率，简称 IR。

它衡量的是：

```text
每承担一单位主动风险，策略获得了多少主动收益。
```

在 MVP 里，我们使用：

```text
information_ratio = active_return 年化均值 / tracking_error
```

它和夏普比率很像，但参照物不同。

夏普比率大致是在问：

```text
每承担一单位总波动，策略获得多少绝对收益？
```

信息比率是在问：

```text
每承担一单位相对基准的波动，策略获得多少超额收益？
```

这两个问题不一样。

一个策略夏普高，不代表它相对基准一定好。

一个策略信息比率高，说明它在“跑赢基准”这件事上更稳定。

所以在量化研究里，IR 是非常常见的相对评价指标。

## 九、为什么这个模块放在 analysis？

这次新增文件：

```text
analysis/benchmark.py
```

而不是放在：

```text
backtest/
models/
live/
```

原因是它的职责更接近“分析”，不是“交易”。

它不决定买什么。

它不决定买多少。

它不改变回测撮合。

它只是拿已经跑出来的净值曲线，和一个基准曲线做比较。

所以它适合放在：

```text
analysis/
```

当前 `analysis/` 下面的职责变成：

```text
performance.py
计算绝对绩效：年化收益、波动、夏普、最大回撤

benchmark.py
计算相对绩效：基准、超额收益、跟踪误差、信息比率

plotting.py
画净值、超额净值、IC、权重等图

ic.py
做因子预测能力检验
```

这个分层比较清楚。

回测层只负责生成净值。

分析层负责解释净值。

## 十、它在 main.py 里的位置

现在 `main.py` 的主流程可以理解成：

```text
1. 读取配置
2. 得到行情价格
3. 构建因子面板
4. 计算 IC
5. 跑单因子回测
6. 跑融合回测
7. 构造股票池等权基准
8. 计算超额收益指标
9. 保存配置、绩效、调仓日志
10. 保存净值图、超额净值图、IC 图、权重图
```

注意第 7、8 步放在所有策略回测之后。

原因很自然：

```text
只有先有策略净值，才能和基准做比较。
```

基准本身也会作为一条净值曲线加入 `nav_compare.png`。

但它不会进入：

```text
rebalance_logs/
```

因为基准不是一条 Top-K 策略，没有调仓选股日志。

它只是一个参照组。

## 十一、为什么不一开始就接指数基准？

未来当然可以接。

比如：

```text
沪深 300
中证 500
中证 1000
创业板指
行业指数
```

但在 MVP 阶段，我更倾向于先用股票池等权基准。

原因有三个。

### 1. 不依赖外部数据

指数数据需要额外接口。

如果接口权限、字段、交易日对齐没处理好，就会给 MVP 增加新的不稳定点。

股票池等权基准直接来自现有价格宽表。

只要回测能跑，基准就能算。

### 2. 和策略 universe 一致

策略在什么股票池里选，就拿什么股票池做平均表现。

这比随便拿一个指数更公平。

否则可能出现：

```text
策略池偏大盘，但拿中证 1000 做基准；
策略池偏小盘，但拿沪深 300 做基准。
```

这样比较出来的结果会混入风格差异。

### 3. 工程上更容易验证

股票池等权基准逻辑简单，单测也容易写。

这次我们新增了：

```text
tests/test_benchmark.py
```

用一个很小的价格表验证：

- 等权基准净值是否按平均收益累乘。
- 超额净值是否在策略跑赢时上升。
- 超额指标是否能正常输出。

MVP 里先把最小闭环做稳，再扩展指数基准，是更稳的工程顺序。


```text

```

## 十五、这次升级的意义

这一篇其实是在给 MVP 补一个很重要的研究习惯：

```text
任何策略结果，都要问“相对谁”。
```

没有基准时，我们只能看绝对表现。

有了基准后，我们才能看：

```text
策略是否真的创造了相对价值。
```

在工程上，这次升级让主流程多了一层解释能力：

```text
回测层：生成策略净值
绩效层：解释绝对表现
基准层：解释相对表现
落盘层：保存实验证据
```

它没有让策略本身更复杂。

但它让我们判断策略时更不容易被市场环境误导。

这是一个量化研究 MVP 从“能跑”走向“能分析”的关键小步。
